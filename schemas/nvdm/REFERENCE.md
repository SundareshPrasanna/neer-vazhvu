# NVDM reference

Generated by `scripts/build_nvdm_reference.py` from the schemas in this directory, the scope
registry and the constants in `scripts/validate_nvdm.py`. Do not edit by hand: change the
source and regenerate. [RULES.md](RULES.md) explains what each item means.

## Envelope fields

Descriptions are the schema's own. A type in backticks names another table in this section.
`date` is a string: ISO 8601 date, year-month, or year, with bounded month/day. Never prose. Pattern: `^\d{4}(-(0[1-9]|1[0-2])(-(0[1-9]|[12]\d|3[01]))?)?$`.

### `envelope`

| field | required | type | description |
|---|---|---|---|
| `nvdm` | yes | string, pattern `^1\.\d+$` | NVDM version the artifact is written against, as MAJOR.MINOR (spec Part 11). |
| `dataset` | yes | string, pattern `^[a-z-]+/[a-z0-9-]+$` | <family>/<stem>, must agree with the file path (spec 4.2, 4.3). |
| `scope` | yes | `scope` | The one place or water system the artifact is about (spec 4.1). |
| `provenance` | yes | `provenance` | Where the values came from and how this file was produced (spec Part 5). |
| `projection` | no | `projection` | Optional. Marks the artifact as a view of evidence owned by another scope (spec 5.7). |
| `ext` | no | object | Per-scope extensions, namespaced by concern (spec 6.3). |

### `scope`

| field | required | type | description |
|---|---|---|---|
| `kind` | yes | one of `city`, `region`, `basin`, `corridor`, `waterway`, `district`, `state`, `body`, `block`, `gram-panchayat`, `country` | Closed list; appending a kind is a one-line MINOR change (spec 4.1). Must equal the kind the scope registry records for the id. block and gram-panchayat are reserved for standalone places: the block and Gram Panchayat records of a district live inside district-scoped artifacts. country, added in 1.1, is the root every place's administrative-parent chain reaches. |
| `id` | yes | string, pattern `^[a-z][a-z0-9-]*$` | Registered scope id (spec 4.1). Stable forever and opaque: never parsed. Hierarchy and external identities live in the registry's relations and refs. |

### `provenance`

| field | required | type | description |
|---|---|---|---|
| `sources` | yes | array of `source` | External upstreams only; NVDM artifacts consumed as inputs go in internal_inputs. Every source must be accountable (spec 5.3): a registry id whose dependsOn names this file, or closed with as_of. May be empty only for a claim-dataset compilation, whose per-record citations carry accountability, or a self-authored artifact naming produced_by, and always with an explanatory note. |
| `method` | yes | one of `manual`, `scrape`, `api`, `pdf-extract`, `gee`, `derived`, `mixed` | How the values were obtained (spec 5.2). derived and gee artifacts must name produced_by and, when they list sources, give at least one the role input. |
| `produced_at` | yes | `date` | When this file was generated or compiled. The writers advance it on every rewrite. |
| `produced_by` | no | string | Generator script path, or "manual". |
| `note` | no | string or array | Caveats, gaps and explanations, as a string or an array. Required when sources is empty. |
| `internal_inputs` | no | array of string | Repo-relative paths of the NVDM artifacts this artifact is derived from (spec 5.4). The validator caps the artifact at L2 while any listed input is below L2, absent from the catalogue or itself capped. derived, gee and mixed artifacts must declare it to reach L3, as [] when there are none. |
| `conventions` | no | object | Declared traps: sign conventions, aggregation basis, comparability breaks (spec 7.5). |
| `rights_determination` | no | `rights_determination` | Optional audited judgement about a named restricted input (spec 5.5). |

### `source`

| field | required | type | description |
|---|---|---|---|
| `id` | no | string | Headwaters source-registry id. Required for a living source (anything that could publish again); the registry entry's dependsOn must name this file (spec 5.3). |
| `closed` | no | boolean | Explicit declaration that this upstream will never publish again (a dated letter, a one-time report). A closed source needs no registry id but must carry as_of. as_of alone is not a closed-source marker: living sources have evidence dates too. |
| `role` | no | one of `asserts`, `input`, `methodology` | Who stands behind the values (spec 5.2). asserts (the default): the publisher stands behind them and this file transports them. input: raw material for values computed here. methodology: a cited method, not data. |
| `title` | yes | string | What the source is, specific enough to find it again. |
| `publisher` | yes | string | The body that published it. |
| `url` | no | string | Where it was read. |
| `license` | no | string | The upstream's licence terms (spec Part 5). Required at L3 on every source whose role is not methodology. On a source with a registry id the string must equal the registry's. |
| `as_of` | no | `date` | The period the source's data describes. Required on a closed source. |
| `retrieved` | no | `date` | When the source was acquired. |

### `projection`

Present when this artifact is an administrative VIEW of canonical evidence owned by another scope (spec Part 5). Absence asserts the artifact is canonical for its scope.

| field | required | type | description |
|---|---|---|---|
| `of` | yes | `scope` | The scope that owns the canonical evidence. |
| `method` | yes | one of `direct-published`, `identifier-crosswalk`, `spatial-intersection`, `area-weighted`, `station-assignment`, `interpolation`, `service-relation`, `administrative-rollup`, `administrative-proxy`, `expert-mapped` | How the view was drawn from the canonical evidence. |
| `limitations` | no | array of string | What the view cannot show, one sentence each. |

### `rights_determination`

An audited, artifact-level judgement that a NAMED restricted input does not encumber THIS file, scored by scripts/nvdm-encumbrance-report.py. It can only lift 'restricted' to 'gov-attribution'; it can never clear nc, share-alike or vague, and can never reach clean-open. It is not a note and not a blanket policy: every field is checked, and a determination that names an input which no longer restricts the artifact is a loud audit error rather than a silent pass.

| field | required | type | description |
|---|---|---|---|
| `basis` | yes | one of `derived-facts` | The doctrine relied on. 'derived-facts': the payload is an indicator computed here from measured values, and there is no copyright in facts (Eastern Book Company v D.B. Modak, (2008) 1 SCC 1), so the upstream's terms over ITS OWN document do not reach it. New bases require the classifier to be taught what they may clear. |
| `clears` | yes | array of string, min length 1, pattern `^([a-z0-9][a-z0-9-]*\|[A-Za-z0-9_./-]+#inline)$`, at least 1 | Exactly which restricted inputs this determination covers. Coverage is a superset test: any restricted contributor reaching this artifact that is NOT named here leaves it restricted. This is what stops a determination from being broader than its own reasoning. |
| `reasoning` | yes | string, min length 80 | Why the basis applies TO THIS FILE, naming what the payload actually contains. A generic sentence copied across a directory is the failure this length floor exists to discourage. |
| `reviewed_on` | yes | `date` | When the judgement was made, so it can be re-examined. |

## Scope registry entry

### `entry`

| field | required | type | description |
|---|---|---|---|
| `kind` | yes | one of `city`, `region`, `basin`, `corridor`, `waterway`, `district`, `state`, `body`, `block`, `gram-panchayat`, `country` | What the scope is; an artifact's scope.kind must equal it (spec 4.1). |
| `name` | yes | string, min length 1 | Display name. It may change; the id may not. |
| `refs` | no | array of `ref` | The scope's identities in external systems (spec 4.4). |
| `relations` | no | array of `relation` | Typed links to other registered scopes (spec 4.5). |

### `ref`

| field | required | type | description |
|---|---|---|---|
| `system` | yes | one of `iso3166-1`, `iso3166-2`, `lgd`, `census-2011` | The external identifier system. lgd is India's Local Government Directory; census-2011 is the Census of India 2011. |
| `level` | yes | one of `country`, `state`, `union-territory`, `district` | The administrative level the code identifies in that system. |
| `code` | yes | string, min length 1 | The identifier, as a string. One system and code pair belongs to one scope. |
| `as_of` | no | `date` | Source vintage of the code, where known. |

### `relation`

| field | required | type | description |
|---|---|---|---|
| `type` | yes | one of `administrative-parent`, `intersects`, `projection-of` | administrative-parent: place to parent place. intersects: water system to a place it crosses, geometry only, never supply or entitlement. projection-of: an administrative view to its canonical water system (the registry form of the envelope's projection.of). See spec 4.5. |
| `target` | yes | string, pattern `^[a-z][a-z0-9-]*$` | The id of another registered scope. |
| `method` | no | one of `geometry`, `published`, `crosswalk`, `manual` | How the relation was established (spec 4.5). Required, with evidence, on every intersects (enforced by scripts/validate_nvdm.py). geometry: the system's geometry in the repo was tested against the place's polygon. published: the source's publisher states it. crosswalk: joined through an identifier. manual: a reviewed mapping. |
| `evidence` | no | string, min length 1 | A repo path or URL that lets the relation be re-checked: for geometry, the boundary or centerline that was tested. |
